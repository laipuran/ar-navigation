# 后端内部接口 Spec

状态：导航核心与LLM工具适配已实现。本文描述Rust进程内导航职责，不定义REST端点、HTTP状态码或网络服务。具体类型、路径与指引结构、等长路线规则、加载方式及实现边界见[后端说明](../../backend/README.md)与[`navigation.rs`](../../backend/src/navigation.rs)；下文部分类型仍为职责草图。对话编排位于`assistant`模块，HTTP契约见[对话接口](api.md)。

## 1. 范围与已有约定

- 消防图作为室内拓扑底稿，现场核验通行关系并补测距离，使用JSON维护。
- Room携带name，表示房间有标示的前门外到达点，不进入房间内部。
- Gate携带description；Stairs表示楼梯平台或出入口；Junction携带neighbors。
- Edge是连接关系的唯一来源，默认双向；Junction.neighbors只提供俯视顺时针顺序，用于转向指引。
- FloorId为整数，其高低顺序语义尚待确认。
- 首版计算单栋楼内、总行走距离最短的路线。
- 不包含AR、连续定位、账号、地图编辑、路线历史或跨楼栋路径规划。

## 2. 内部接口概览

以下为职责与类型草图，不是已经实现的函数签名；BuildingId、BuildingSummary、NodeQuery、Route和NavigationError等类型的具体定义尚待确认。

```rust,ignore
fn list_buildings(&self) -> Vec<BuildingSummary>;

fn search_nodes(
    &self,
    building_id: &BuildingId,
    query: &NodeQuery,
) -> Result<Vec<Node>, NavigationError>;

fn get_node(
    &self,
    building_id: &BuildingId,
    node_id: &NodeId,
) -> Result<Node, NavigationError>;

fn find_route(
    &self,
    building_id: &BuildingId,
    from: &NodeId,
    to: &NodeId,
) -> Result<Route, NavigationError>;
```

building_id标识已加载的楼栋数据集，节点ID在该数据集内唯一。以上能力由后端内部直接调用，不监听端口、不回调自身HTTP接口。是否采用一个具体类型封装及借用/所有权细节，实施时再决定，不预先增加trait或独立进程。

## 3. 列出楼栋

`list_buildings`返回当前可用楼栋的标识和可辨认的名称，具体元数据字段待定。没有可用数据时返回空列表。

未通过数据校验的楼栋不得进入可用列表。

## 4. 搜索节点

`search_nodes`接受楼栋标识与可选筛选条件：

- 文本：对Room.name或Gate.description做字符串包含匹配，不使用模型猜测。
- 节点类型：room、gate、stairs、junction。
- 楼层：FloorId。

语义：

- 多条件同时存在时取交集。
- 不提供文本时，可以按类型、楼层列出节点。
- 没有匹配返回空列表，不作为错误。
- 同名节点全部保留，由调用方处理歧义，不自动选择其中一个。
- 不通过名称解析出不存在的房间、楼层或通道。

## 5. 获取节点

`get_node`根据明确的楼栋与NodeId返回节点。楼栋不存在与节点不存在是不同错误。

它不承担名称搜索、图数据编辑或导航起点推测。

## 6. 计算路线

`find_route`只接受明确的节点标识，不兼做名称查询。返回结果应包含：

- 总行走距离distance_m。
- 按行走顺序排列的路径path。
- 根据该路径确定性生成的指引steps。

path如何组织节点与连接、steps的枚举与字段，下一轮单独确定。

规则：

- 按边的实际行走距离累加并选择最短路线；等长路线的选择规则待定，但应可复现。
- 边默认双向，同一条边支持反向行走。
- 起终点不存在时报告对应错误；均存在但断连时报告NoRoute。
- 起终点相同：零距离，路径只有该节点，并生成到达指引。
- 经过Junction时，用前一节点、当前节点和后一节点确定顺时针出口序号；来路不计入出口，返回来路单独表示。
- 以Junction为起点且缺少来向时，不编造出口序号，应指明下一个节点或要求补充信息。
- 楼梯指引关联两端楼层；FloorId高低语义未确定前，不自行推断上楼或下楼。
- 路线和指引由业务逻辑生成，不依赖LLM决定连通关系、距离或出口顺序。

## 7. 业务错误

候选错误分类：InvalidInput、BuildingNotFound、NodeNotFound、NoRoute。最终Rust枚举与错误上下文待实现前确认。

这些是进程内的业务结果，不绑定HTTP状态码。工具适配层可以把它们转换成模型能理解的结构化结果；模型需要据此追问或解释，不伪造成功。

## 8. 数据加载与校验

- JSON加载后先校验，再构建内存图；不在每次工具调用中重新解析文件。
- 校验节点标识唯一、引用有效、边两端不同、无重复无向边、距离为有限正数。
- Junction.neighbors必须与Edge确定的实际邻居恰好一致，无重复、遗漏或额外节点。
- Walk限同层连接，StairFlight连接楼梯节点；现场核验决定跨层楼梯实际连通情况。
- 无效数据集不得用于查询与算路，不在运行时静默忽略坏边。
- 采集草稿是否允许未知距离、楼栋与楼层元数据及序列化标签尚待schema确认。

## 9. 智能体如何调用

模型工具的候选能力与上述内部接口对应，但工具名和参数schema不要求等于Rust函数名或签名。

```text
模型返回工具名与参数
  → 后端检查允许的工具、参数与调用预算
  → 工具适配层调用内部查询或路径接口
  → 业务结果转换成结构化工具结果
  → 交回模型继续解释或追问
```

- 模型只提出调用，后端执行；不请求自己的REST接口。
- 只允许校园数据查询和路线计算，不开放任意URL、文件、SQL或命令执行。
- 缺少楼栋、起点或候选不唯一时追问，不默认用户所在位置。
- 工具循环有次数和超时上限；当前默认值与配置见后端说明。
- 对外展示的路线必须明确关联到后端真实计算的结果，不能解析模型文本重建，也不能随意取多次调用中的最后一次结果。

## 10. 后续测试应验证的行为

- 搜索筛选生效，同名候选完整，无匹配返回空列表。
- 双向通行、最短路线、距离累加、跨层连接、断连和同点路线。
- 不同来向的出口计数正确；顺时针列表循环换首项不影响指引。
- Junction起点不伪造来向，非法图数据拒绝加载。
- 未知工具、非法参数和预算耗尽不继续执行；失败不会生成虚假路线。

不添加仅构造对象再检查赋值的测试。
